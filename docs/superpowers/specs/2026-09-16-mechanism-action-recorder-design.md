# 机械机构动作录入与测试设计

## 目标

在 Qt 上位机中新增独立的“动作录入”页面，面向
`test/mecanum_jog` 文本调试固件记录、编辑和测试机械机构动作。动作文件保存在
上位机本地，可导出为与实际固件兼容的 C 动作表。

本功能只覆盖机械机构，不包含底盘移动、地图导航或完整比赛流程。5、6 号电机没有
编码器位置回读和原点开关，因此所有位置均为人工初始化后的命令积分估计，界面和协议
不得把它描述为真实测量位置。

## 范围

### 包含

- 人工初始化 5 号升降、6 号横移和 4 号云台的当前位置。
- 为每个动作文件保存一套自定义初始状态。
- 记录组合机械姿态、夹爪、物块平台、独立舵机和等待步骤。
- 编辑步骤顺序并执行选中步骤、局部回放或完整单次回放。
- 回到当前动作文件定义的初始状态。
- JSON 导入导出和 C 动作表导出。
- 在 `test/mecanum_jog` 中增加机构位置状态、组合姿态命令和通用动作表执行器。

### 不包含

- 底盘动作或路线编排。
- 自动循环回放。
- 向 STM32 Flash 动态下载动作表。
- 编码器、原点开关或绝对位置传感器支持。
- 自动接入完整比赛任务流程。

## 用户流程

1. 连接 `mecanum_jog` 文本固件。
2. 使用现有 5、6 号电机点动和舵机控件，把机构人工移动到已知姿态。
3. 在动作录入页填写当前横移、升降和云台位置，点击“初始化并设为初始姿态”。
4. 调整目标姿态并将当前参数记录为动作步骤，或添加夹爪、平台、舵机和等待步骤。
5. 使用“执行选中步骤”逐步验证，确认后进行一次局部或完整回放。
6. 保存 JSON；需要固化到程序时导出 C 动作表。

发生停止、急停、断连、心跳超时、CAN 故障、动作超时，或绕过姿态控制直接点动
5/6 号电机后，位置状态立即失效。此时必须重新人工摆放并初始化，不能从中间估计位置
继续回放或回到初始位置。

## 上位机页面

新增独立的 `MechanismActionPage`，导航名称为“动作录入”。该页面仅在
`mecanum_jog` 文本协议模式启用；标准二进制协议下禁用并说明需要切换设备模式。

页面分为四个区域：

1. 初始化与状态
   - 当前估计横移、升降、云台位置及有效/无效状态。
   - 人工当前位置输入。
   - “初始化并设为初始姿态”和“读取状态”。
   - 持续显示“命令积分估计，非真实位置”。
2. 步骤编辑
   - 组合机械姿态：横移/升降/云台目标，以及两轴速度、加速度和云台插补速度。
   - 夹爪：开、合。
   - 物块平台：位置 1、2、3。
   - 独立舵机：通道 2、3、4 和目标角度。
   - 等待：毫秒数。
3. 步骤表
   - 显示序号、类型、主要参数和步骤后等待时间。
   - 支持新增、修改、复制、删除、上移、下移和清空。
   - 执行期间锁定编辑操作，并高亮当前步骤。
4. 测试与文件
   - 执行选中步骤、从选中步骤开始、完整测试一次、停止、回到初始位置。
   - 打开 JSON、保存 JSON、另存为和导出 C 动作表。

完整或局部回放只进行一次，不提供自动循环。开始回放时统一确认一次；任何步骤的电机
速度超过 120 RPM 时，再显示一次明确的高速机构动作确认。停止按钮始终可用。

## 动作数据模型

动作文件包含版本、名称、初始状态和有序步骤：

```json
{
  "version": 1,
  "name": "grasp_red",
  "initialState": {
    "horizontalDmm": 0,
    "liftDmm": 0,
    "turretDdeg": 684,
    "horizontalRpm": 30,
    "horizontalAccel": 50,
    "liftRpm": 30,
    "liftAccel": 50,
    "turretDps10": 130,
    "gripper": "open",
    "platform": 1,
    "gripperOpenDeg": 45,
    "gripperCloseDeg": 6,
    "platformDeg": [20, 139, 256]
  },
  "steps": [
    {
      "type": "pose",
      "horizontalDmm": -480,
      "liftDmm": 250,
      "turretDdeg": 1350,
      "horizontalRpm": 30,
      "horizontalAccel": 50,
      "liftRpm": 30,
      "liftAccel": 50,
      "turretDps10": 130,
      "waitMs": 500
    },
    {
      "type": "gripper",
      "state": "close",
      "waitMs": 300
    }
  ]
}
```

整数缩放规则：`Dmm` 为 0.1 mm，`Ddeg` 为 0.1°，`Dps10` 为 0.1°/s。
使用整数可避免 JSON 与文本协议之间的浮点格式差异。

保存使用 `QSaveFile` 原子替换。加载时严格校验版本、必需字段、枚举和参数范围；文件
无效时保留当前未保存动作，不进行部分导入。

## 文本协议

固件接收缓冲区扩大到足以容纳最长机构命令，并继续拒绝溢出输入。新增命令：

```text
mech init H L T
mech pose H L T HR HA LR LA TS
mech status
```

参数定义：

| 参数 | 含义 | 范围 |
| --- | --- | --- |
| `H` | 6 号横移，0.1 mm | -1220..650 |
| `L` | 5 号升降，0.1 mm | 0..1350 |
| `T` | 4 号云台，0.1° | 0..3600 |
| `HR`、`LR` | 两轴速度，RPM | 10..2000 |
| `HA`、`LA` | 两轴加速度 | 1..240 |
| `TS` | 云台速度，0.1°/s | 10..300 |

`mech init` 只登记人工摆放位置，不产生运动，不需要 `arm`，但要求所有运动状态空闲。
`mech pose` 必须先完成现有单次 `arm` 握手，并且机构位置有效。

结构化输出：

```text
MECH INIT h=<H> l=<L> t=<T>
MECH RUN h=<H> l=<L> t=<T>
MECH POS h=<H> l=<L> t=<T>
MECH DONE h=<H> l=<L> t=<T>
MECH INVALID reason=<reason>
ERR MECH: <message>
```

`MECH POS` 约每 200 ms 输出一次估计位置。上位机解析这些状态，用于页面显示、回放推进
和按钮门控。

## 固件机构控制

参考 `yyb_stm32` 的机构参数：

- 5 号升降：80 pulse/mm，允许 0..135 mm。
- 6 号横移：25.465 pulse/mm，允许 -122..65 mm。
- 目标增量为正时方向位为 0，为负时方向位为 1。

组合姿态启动时：

1. 校验位置状态、范围、速度和加速度。
2. 计算 5、6 号电机相对当前位置的脉冲数。
3. 自动使能 5、6 号电机。
4. 使用同步标志装载两轴位置命令，并启动 4 号舵机插补。
5. 发送 CAN 同步启动命令，使两轴同时开始。
6. 根据距离、速度、加速度和舵机角差计算保守超时与估计进度。
7. 正常完成后提交目标为新的估计位置并输出 `MECH DONE`。

固件没有到位传感器，因此 `MECH DONE` 只表示保守估算时间结束。发生故障时不能提交
目标位置，而是停止所有执行器、输出 `MECH INVALID` 并要求重新初始化。

现有 `motor 5|6 0|1` 点动命令会改变机构位置但没有可用位移信息，因此执行后必须使
机构位置失效。`stop`、`!`、`disable`、主机心跳超时和 CAN 故障同样使其失效。

夹爪、平台和独立舵机步骤继续复用现有 `servo` 命令及 `DONE servo=` 回报：

- 夹爪默认命名角度：合 6°、开 45°。
- 平台默认命名角度：位置 1 为 20°、位置 2 为 139°、位置 3 为 256°。
- 独立舵机仍遵守通道 2/3 为 0..270°、通道 4 为 0..360°。

命名角度写入 JSON，后续标定时可在动作文件中更新，不隐藏为不可见常量。

## 回放状态机

上位机负责本地 JSON 动作的测试调度，固件一次只接收一个动作：

1. 检查连接、机构初始化状态、步骤范围和高速确认。
2. 对姿态步骤执行 `arm`，收到 `ARMED` 后发送 `mech pose`。
3. 等待 `MECH DONE`，再等待该步骤的 `waitMs`。
4. 对舵机类步骤发送对应 `servo` 命令，等待 `DONE servo=`，再等待 `waitMs`。
5. 纯等待步骤只启动上位机单次定时器。
6. 推进到下一步骤，或报告完成。

单步测试、从选中步骤开始和完整测试共用同一状态机。回到初始位置也使用该状态机：
先执行初始组合姿态，再依次恢复夹爪和平台状态。

任一错误、拒绝、超时、断连、停止或急停都会清空待执行步骤并停止定时器。页面保留
失败步骤高亮和错误文本，不自动重试运动命令。

## C 动作表导出

固件增加兼容 ARMCC/C99 的 `MechanismAction` 定义和非阻塞动作表执行器。导出文件同时
生成初始状态常量，并使用命名宏生成静态数组：

```c
static const MechanismInitialState grasp_red_initial =
    MECH_INITIAL_STATE(0, 0, 684, 30, 50, 30, 50, 130,
                       45, 6, 20, 139, 256);

static const MechanismAction grasp_red[] = {
    MECH_POSE(-480, 250, 1350, 30, 50, 30, 50, 130, 500),
    MECH_GRIPPER_CLOSE(300),
    MECH_WAIT(500),
};

#define GRASP_RED_COUNT \
    ((uint16_t)(sizeof(grasp_red) / sizeof(grasp_red[0])))
```

动作表执行器与文本命令调用同一个机构控制入口，确保范围、脉冲换算、失效逻辑和完成
判断一致。导出的数组不会被自动加入比赛流程；使用者必须在明确位置注册或调用。

## 安全约束

- 默认速度为 30 RPM、默认加速度为 50、默认云台速度为 13°/s。
- 任何步骤的电机速度超过 120 RPM 时，上位机必须显示高速二次确认。
- 固件始终执行硬范围校验，不能依赖上位机校验。
- 测试开始前仍需现有单次 `arm` 授权。
- 普通停止和全局急停在动作录入页始终可用。
- 断连后不自动恢复回放，也不保留有效位置状态。
- 首次实机验证按人工低速初始化、单轴、低速组合姿态、高速组合姿态的顺序进行。

## 测试

### 固件测试

- 有符号 0.1 mm/0.1° 参数解析与边界拒绝。
- 5、6 号电机方向和脉冲换算。
- 两轴同步装载与同步启动顺序。
- 云台速度、组合完成时间和 200 ms 位置回报。
- 重复目标、未初始化、忙碌、非法速度和超时。
- 停止、急停、心跳、CAN 故障和直接点动后的位置失效。
- C 动作表各步骤类型、推进、停止和错误中止。

### Qt 测试

- 页面只在文本协议模式启用。
- 初始化命令、`arm -> mech pose` 顺序和状态行解析。
- 步骤新增、修改、复制、删除和重排。
- JSON 往返、版本和范围错误拒绝、原子保存。
- C 标识符清理、动作宏参数和步骤顺序导出。
- 单步、局部、完整回放和回到初始位置。
- 高速二次确认、按钮门控、步骤超时、停止和断连清理。
- 标准二进制协议页面回归。

只运行相关 Qt/C 单元测试和协议状态机测试，不执行完整 Keil 构建；最终固件构建和实机
