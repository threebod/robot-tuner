# 机器人调试上位机设计规格

日期：2026-09-07

## 1. 目标

在 `upper_computer/` 中创建一个面向 Windows 的 Qt 6/C++ 调试上位机，用于通过有线 USB 转串口或 HC-05 蓝牙虚拟串口连接 STM32F407，完成参数读写、状态监控、HWT101 数据显示、原始串口调试和受控动作测试。

参数仅实时写入 STM32 RAM。调试得到最终数值后，由开发者手工修改 STM32 源码中的默认值。本项目不写 STM32 Flash，也不自动修改固件源码。

## 2. 已确认范围

首版包含：

- Windows 桌面程序，使用 Qt 6、C++、Qt Widgets 和 CMake。
- 有线 USB-UART 与 HC-05 蓝牙虚拟串口，界面一次只连接一个 COM 口。
- 底盘 PID、运动速度、加速度和距离参数的读取与 RAM 写入。
- 机械臂、舵机、升降机构和夹爪命名位置参数的读取与 RAM 写入。
- HWT101 加速度、角速度、姿态数据显示、曲线和零偏校准命令。
- 底盘点动、旋转、机械臂位置、舵机点动等受控动作测试。
- HEX/ASCII 原始串口收发、时间戳、协议帧日志和错误统计。
- K230/MaixCAM 视觉页面入口与接口状态占位。
- 通过 `HOST_DEBUG_MODE` 编译期开关选择独立上位机调试循环或原有比赛流程。

首版不包含：

- K230 或 MaixCAM 视觉识别算法、阈值调节和画面显示。
- 参数写入 STM32 Flash。
- 同时连接有线和无线通道。
- 自动生成或改写 STM32 业务代码中的最终参数。
- 网络通信、用户账户、远程升级和数据库。
- 在比赛阻塞流程运行期间保持上位机在线。

## 3. 现有硬件接口与分配

- USART1：保留给 K230/MaixCAM 视觉端，继续兼容现有 `0xFF + 9 字节 + 0xFE` 视觉结果协议。
- USART2：连接 HWT101，由 STM32 采集并向上位机转发。
- USART3：新增有线上位机通道，使用 PB10/PB11，默认 115200 baud。
- UART5：连接 HC-05，默认 9600 baud；保留现有 `0x04 0x05 ... 0x06` 蓝牙帧。
- USART6：保留现有 HMI 通信，不纳入本次改造。

PB10/PB11 在固件接入前必须结合实物接线和 PCB 再确认一次。若实物存在占用，只替换 USART3 的硬件适配层，不改变上位机协议和业务模块。

## 4. 总体架构

### 4.1 Qt 上位机

上位机分为四层：

1. 界面层：连接栏、分页工作台、状态提示和操作确认。
2. 设备服务层：参数服务、遥测服务、动作测试服务和设备状态。
3. 协议层：帧编码、增量解析、请求序号、超时、ACK 和错误映射。
4. 串口层：基于 `QSerialPort` 的端口枚举、打开、关闭、收发和错误通知。

所有串口 I/O 使用 Qt 事件循环，不为首版额外创建线程。协议解析器接收任意长度的数据块，必须正确处理半包、粘包和噪声字节。遥测数据进入固定容量环形缓冲区，界面按固定刷新周期绘制，避免高频重绘阻塞串口处理。

### 4.2 STM32 固件

STM32 侧新增独立纯 C 协议模块，包含：

- 字节流解析器；
- CRC16 校验；
- 命令分发；
- 参数 ID 到现有 RAM 变量的映射；
- 遥测订阅与发送；
- 调试动作安全状态机；
- USART3 和 UART5 的薄适配层。

协议模块不直接包含电机、舵机或 IMU 驱动逻辑，而是调用明确的参数访问和动作接口。对 `yyb_stm32/` 的修改限制在串口初始化、中断投递、主循环协议处理、参数入口和安全停止入口，不重写现有比赛任务流程。

现有比赛任务包含大量阻塞式动作和调试用永久循环，因此首版采用独立调试模式。`host_config.h` 提供 `HOST_DEBUG_MODE` 编译期开关：值为 `1` 时，外设初始化完成后进入持续处理上位机协议的调试循环，不进入比赛任务；值为 `0` 时，执行原有比赛流程，不在比赛流程中提供实时上位机服务。开发调参阶段使用 `1`，比赛固件构建前显式改为 `0`。

## 5. 界面设计

采用“分页工作台”布局：顶部为永久连接栏与急停按钮，左侧为页面导航，右侧为当前工作页。

### 5.1 顶部连接栏

- COM 口选择、刷新、波特率选择、连接和断开。
- 连接方式不单独区分，Windows 中的 USB-UART 和 HC-05 都按 COM 口处理。
- 显示串口状态、设备握手状态、固件版本、最近响应时间和错误状态。
- 急停按钮始终可见；连接后不受当前页面限制。

### 5.2 页面

1. 总览：设备信息、连接质量、控制状态、IMU 摘要、最近错误。
2. 底盘与 PID：PID 配置组 0～4，Kp/Ki/Kd、积分限幅、输出限幅，以及通用速度、加速度和距离参数。
3. 机械臂与舵机：按现有业务含义显示命名位置、角度、速度、升降和夹爪参数。
4. HWT101：加速度、角速度、姿态角数值与曲线，遥测频率和校准操作。
5. 动作测试：底盘点动、旋转、机构单步动作和停止。
6. 串口终端：HEX/ASCII 显示与发送、时间戳、TX/RX 方向、协议帧解析结果和错误计数。
7. 视觉：显示“首版未实现”，保留 K230/MaixCAM 接口状态区域，不提供无效控件。

参数页提供“从 STM32 读取”“写入 RAM”和“恢复本次连接初值”。“恢复本次连接初值”使用首次握手后读取到的设备值，不使用电脑内置假定值。

## 6. 新二进制协议

### 6.1 帧格式

按字节排列：

`AA 55 | version:u8 | flags:u8 | sequence:u8 | command:u8 | length:u16_le | payload:length | crc16:u16_le`

- 帧头固定为 `0xAA 0x55`。
- 首版版本号为 `0x01`。
- `flags` 标识请求、响应、主动事件或错误。
- `sequence` 由请求端递增，响应沿用请求序号。
- `length` 最大为 128；超长帧立即丢弃并重新寻找帧头。
- 多字节整数、IEEE 754 单精度浮点数和 CRC 字段均采用小端序。
- CRC16 覆盖从 `version` 到 `payload` 的全部字节；算法采用 CRC-16/CCITT-FALSE，初值 `0xFFFF`，多项式 `0x1021`，不反射，结果不异或。

### 6.2 命令集合

- `HELLO`：握手并返回协议版本、固件版本和设备能力位。
- `GET_STATUS`：读取控制状态、急停状态和错误码。
- `GET_PARAM_GROUP`：按参数组读取当前 RAM 值。
- `SET_PARAM_GROUP`：按参数 ID、类型和值批量写入 RAM，并返回逐项结果。
- `SET_TELEMETRY`：订阅或停止 IMU、PID 和设备状态遥测，并设置周期。
- `IMU_CALIBRATE`：请求 HWT101 零偏校准并返回执行状态。
- `TEST_UNLOCK`：在设备端开启限时调试动作权限。
- `TEST_ACTION`：执行受范围限制的底盘或机构单步动作。
- `STOP`：停止当前调试动作。
- `EMERGENCY_STOP`：进入锁定急停状态并停止所有受控动作。
- `CLEAR_EMERGENCY_STOP`：在设备静止且条件允许时解除急停。

错误响应至少区分：不支持的版本、不支持的命令、CRC 错误、长度错误、参数不存在、类型错误、参数越界、设备忙、未解锁和急停锁定。

### 6.3 参数模型

每个可调参数具有固定 ID、数据类型、单位、最小值、最大值和所属参数组。Qt 与 STM32 使用同一份人工维护的协议定义文档和匹配枚举；首版不引入代码生成器。

批量写入先完整校验整组数据，再统一应用。只要一项无效，整组拒绝，避免页面参数只写入一半。写入成功后响应中返回设备实际采用的值，Qt 使用返回值更新界面。

### 6.4 双协议兼容

- UART5 收到 `0x04 0x05` 时交给旧 HC-05 帧解析器。
- UART5 或 USART3 收到 `0xAA 0x55` 时交给新上位机协议解析器。
- 其他字节作为噪声丢弃，但可计入诊断统计。
- USART3 只需支持新协议。
- 遥测仅发回最后成功订阅的串口；界面要求用户一次只连接一个通道。

HC-05 在 9600 baud 时，IMU 默认 10 Hz，允许范围 1～20 Hz；USART3 默认 115200 baud，允许范围 1～50 Hz。STM32 可根据链路能力拒绝过高频率并返回实际采用值。

## 7. 安全设计

- 未完成 `HELLO` 握手时，参数写入、校准和动作测试均禁用。
- `HOST_DEBUG_MODE == 0` 时不进入上位机调试循环，也不接受调试动作命令。
- Qt 输入控件与 STM32 参数访问层均执行范围检查。
- 动作测试必须先发送 `TEST_UNLOCK`；解锁 30 秒后、断开后或通信看门狗超时后自动失效。
- 动作命令包含受设备端限制的速度、角度、距离和机构行程。
- 调试动作期间若超过通信看门狗时间未收到有效保活或命令，STM32 执行安全停止。
- 急停在命令分发中具有最高优先级，不等待其他动作完成。
- 解除急停需要显式操作，不能由重新连接自动完成。
- 上位机只有收到成功 ACK 和读回值后，才显示参数已生效。

软件急停不能替代物理急停或断电装置。实机首次联调必须架空驱动轮或移除负载，并使用较低速度上限。

## 8. 错误处理

- 普通请求设定超时，超时后自动重试一次；再次失败则报告错误，不假定成功。
- CRC、长度和版本错误不会进入业务分发。
- 串口拔出、系统串口错误或设备无响应时立即停止发送新动作，锁定动作测试区并清空待处理请求。
- 原始终端显示错误帧和统计，但不能绕过动作解锁与设备端限幅。
- 日志包含时间、方向、命令、序号、结果和必要的原始 HEX；不记录无意义的重复 UI 刷新。

## 10. 测试与验收

### 10.1 自动测试

- Qt 协议编码与解码往返测试。
- 半包、粘包、噪声、错误 CRC、错误长度和超长帧测试。
- 请求序号匹配、超时、单次重试和错误响应测试。
- 参数类型、范围、整组原子校验和设备回读测试。
- 遥测环形缓冲区容量和刷新节流测试。
- 使用假串口/设备替身验证握手、调参、遥测、校准、解锁、动作、急停和断连流程。

STM32 协议核心保持为不依赖外设寄存器的纯 C 模块，使用主机测试程序覆盖帧解析、CRC、参数校验和命令分发。硬件适配层通过 Keil 工程构建检查。

### 10.2 实机验收

- USB-UART 和 HC-05 分别完成连接、握手、读参、写参和读回。
- `HOST_DEBUG_MODE == 1` 时只进入调试循环；设为 `0` 后恢复现有比赛流程入口。
- 断开一个通道后才能在上位机连接另一个通道。
- HWT101 遥测连续稳定，校准有开始、成功或失败反馈。
- 五组 PID 与机构参数写入 RAM 后立即生效，STM32 复位后恢复源码默认值。
- 动作测试在未解锁、越界、超时和急停状态下均被拒绝或安全停止。
- 串口终端能正确显示新协议帧，并保留 UART5 旧协议兼容性。

没有连接实物时，只能声明自动测试和构建结果，不能声明上述实机验收通过。

## 11. 实施边界

首轮实施以可构建、可模拟、协议可靠和安全停止为目标。视觉算法、复杂主题系统、插件化、数据库、网络控制和参数代码生成均留在范围外。任何新增依赖或向 C 盘安装 Qt/工具链的操作，都必须先获得用户批准。
