# 上位机路线编辑设计

日期：2026-10-06

## 已确认的目标

在 Qt 上位机新增“路线编辑”页，像动作组一样编辑、保存和执行路线。
上位机保持串口连接，逐步下发；不将整条路线下载到 STM32 脱机运行。
移动方向相对于执行该步骤时的当前车头。允许补充 STM32 相对距离移动指令。
视觉对准后的位置成为后续相对路线的起点，不反向抵消对准位移。
保留现有固定路线、两轮任务、动作录入和视觉微调页面的入口与行为。

## 用户操作与路线文件

页面分为路线名称、步骤表、选中步骤参数和执行状态四部分，沿用动作录入页的交互风格。
支持添加、删除、复制、上移、下移、修改步骤，以及打开／保存 JSON。
执行入口为测试选中步骤、从选中步骤开始、整段运行、停止。
人工确认步骤显示“确认并继续”；执行期间禁止修改正在执行的路线。
离线可以编辑和保存，运行只在 mecanum_jog 文本协议模式并已连接时启用。

步骤类型如下：

| 类型 | 参数 | 完成条件 |
| --- | --- | --- |
| 相对移动 | 前／后／左／右、距离 mm、速度 RPM | 固件相对移动完成反馈 |
| 转向 | 左／右、角度 1～180° | 对应的 TURN DONE |
| 视觉对准 | 物料颜色 1～6 或圆环 1～3、前后／左右标定比例 | 设置比例确认后启动对准，等待 VISION DONE |
| 动作组 | 导入现有动作组 JSON 的完整内容 | 按原顺序执行，等待各动作对应完成反馈和步骤等待 |
| 等待 | 等待毫秒数 | 上位机定时器完成 |
| 人工确认 | 提示文字 | 用户点击确认并继续 |

动作组作为路线的一步导入，其内容随路线 JSON 保存；执行不依赖原动作组文件路径。
路线编辑器不另建机构动作编辑器，修改机构动作仍在现有动作录入页进行，再重新导入。
执行动作组使用其速度、姿态、夹爪、平台角度与等待参数。
动作组的初始状态是实际状态前提，不在每次调用时发送 mech init 来覆盖位置估计。
机构初始化仍沿用现有动作录入页；执行前确认机构有效，并核对动作组初始状态。
动作组含循环设置时，按该文件的既有有限循环语义执行。

JSON 包含版本、名称和有序步骤列表。校验所有类型、枚举、范围及嵌入动作组。
加载失败保留当前编辑内容；未知版本或未知步骤类型报错，不静默跳过。
执行前对所选执行范围重新验证，运行期间持有步骤快照。
本期不新增路线循环、分支、脚本、地图路径规划或固件 C 表导出。

## 视觉与方向语义

相对移动采用当前车头坐标：前后沿车头轴，左右沿车身横轴。
转向改变后续移动的方向基准。例如左转 90° 后，“前进”沿新的车头方向。
移动步骤不依赖 nav init 和地图绝对坐标；视觉调整使导航估计失效也不妨碍后续相对移动。
不将视觉微调距离加进后续移动，不执行回退，也不将车辆重新移动到旧的名义坐标。
例如“前进 900 mm → 物料对准 → 左转 90° → 前进 500 mm”，最后一步从对准后的位置出发。

视觉步骤内保存并应用自己的前后／左右标定比例，范围沿用固件现有校验。
收到对应比例确认后才启动对准，等待完成后才执行下一步。
物料对准仅对准指定颜色，不隐含夹取；取放由后续动作组负责。
视觉步骤不自动移动机械机构。需要观测姿态时，在对准步骤前插入准备动作组。
未识别到目标时沿用现有持续等待与摄像头通信故障规则，不新增识别总时限。

## 上位机实现边界

- RouteSequenceModel：路线数据、JSON 读写、参数校验，复用 MechanismActionModel 的动作组格式。
- RouteEditorPage：编辑交互和步骤状态显示，不直接操作串口。
- RouteSequenceRunner：顺序执行状态机，等待当前步骤对应反馈，管理定时等待与人工确认。
- MecanumJogClient：增加相对移动、物料对准及相应状态反馈，复用现有 arm 授权、心跳和串口解析。
- MainWindow：注册页面和信号连接；协调路线运行时其他运动入口，避免同时控制同一车辆。

动作组执行复用现有命令格式和模型，避免让路线页依赖另一个页面的按钮或私有函数。
如需共享动作组的下发逻辑，只提取执行所需部分，保留原页面行为，不重写整个动作组编辑器。
完成反馈必须与当前步骤类型及关键参数对应；servo 反馈匹配通道，机构反馈匹配目标姿态。
重复完成反馈及非当前步骤反馈不推进步骤。收到授权、RUN 或已发送回复不视为动作完成。
先登记等待状态，再发命令，处理同步发送失败和槽函数重入。
路线结束释放控制权，错误与停止取消定时器及待发步骤，禁止自动续跑。
停止仍可从其他页面或全局急停触发，停止信号传播到路线执行器。

## STM32 相对移动协议

新增 `move W|S|A|D distance_mm rpm`，W/S/A/D 分别为前／后／左／右。
距离范围 1～2400 mm，速度范围 10～250 RPM；横向有效速度受现有横移上限限制。
沿用现有单次 arm、空闲、IMU 新鲜度、CAN 健康及急停检查。
机构动作、视觉会话、固定路线与相对移动不可并行，拒绝冲突请求。

移动采用现有速度控制、加减速、IMU 航向保持和距离估算方式。
前后使用 routeForwardScale，左右使用 routeLateralScale，保持开始时的实际 IMU 朝向。
不得把直线测试的“定时窗口结束”当成距离到达，也不得用多个 20 mm 视觉点动拼接普通长距离路线。
距目标完成时停止底盘，输出 `MOVE DONE dir=W distance_mm=500` 等对应反馈。
开始输出 `MOVE RUN dir=W distance_mm=500 rpm=100`，故障输出 `ERR MOVE: ...` 并停止。
支持现有 stop、! 和心跳看门狗；运动超时按目标距离与有效速度推算，并留出加减速余量。
成功结束仅清理本段底盘运动状态，不取消机构初始化，不输出 STOP 或触发全局任务取消。
距离完成仍为命令速度积分估计，不宣称提供编码器或外部定位反馈。

既有 `turn L|R degrees` 的成功结束会调用 stopAllMotors；实现时核对并最小调整成功清理路径，
保证转向结束后机构状态仍可用于下一步，并保留故障与用户停止时的全局清理行为。
旧命令和固定路线行为均需回归，不将新 move 步骤绑定到 routeTemplate。

## 失败处理和兼容性

固件拒绝指令、授权超时、运动超时、机构报错、视觉通信故障或用户停止都终止路线。
除人工确认和视觉正常等待外，各下发及运动阶段设置合理完成超时；不能无限等待缺失的完成反馈。
旧固件不支持 move 时显示设备拒绝原因并终止，不退化为时间估算或连续点动。
断连取消上位机后续下发；车辆停车仍依赖现有固件心跳看门狗。
不引入新库，不安装 C 盘依赖，不自动烧录或启动实车运动。

## 验收与验证

1. 模型测试覆盖路线 JSON 往返、嵌入动作组、类型和边界参数、无效文件不覆盖编辑内容。
2. 执行测试覆盖每种步骤正确下发和等待、比例确认先于对准、转向后的相对移动、不回退视觉位移。
3. 执行测试覆盖重复或无关反馈、授权失败、设备错误、停止、断连及定时器取消；不得发下一步。
4. 页面测试覆盖步骤增删修改排序、离线编辑、执行控制、人工确认与运行时互斥。
5. 固件宿主测试覆盖四向距离、横移限速、标定系数、任意实际朝向保持、成功反馈、拒绝并发和故障停止。
6. 回归现有上位机完整 CTest 和固件路线／取料／契约测试，使用现有 Qt/MinGW 环境。
7. 界面截图检查参数控件、步骤列表与中文状态显示；条件允许时执行 Keil 编译并记录结果。
8. 实机验证另行执行：架空方向检查、低速分段距离、转向、视觉后继续、机构动作衔接和急停。
   软件测试不能替代实机验证；交付时明确未完成的硬件验证。

## 实现顺序

先实现相对移动协议及固件宿主验证，再补客户端、路线模型和执行器，最后接入编辑页面与主窗口。
测试执行器时注入模拟设备反馈，不触发硬件。
在实际实现前补充逐项文件修改与验证命令的实施计划，保留当前工作区已有未提交改动。
