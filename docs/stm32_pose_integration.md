# STM32 位姿遥测接入说明

本轮只完成 Qt 上位机的协议预留、解码、显示和本地模拟，**未完成实车定位**。场地图仅
用于调试显示，不作为导航控制依据；比赛现场区域位置可能与规则图的名义尺寸存在偏差。

## 坐标与协议约定

- 场地坐标原点在左下角，X 向右、Y 向上，单位为 mm。
- 航向 0° 指向 +X，逆时针为正；线上使用 `yaw_cdeg:i16`（百分之一度）。
- `POSE_TELEMETRY (0x83)` 固定为 14 字节小端 payload：
  `timestamp_ms:u32 + x_mm:i32 + y_mm:i32 + yaw_cdeg:i16`。
- `SET_POSE (0x22)` 固定为 10 字节小端 payload：
  `x_mm:i32 + y_mm:i32 + yaw_cdeg:i16`。
- HELLO `capabilities` 的 `0x00000001` 位声明位姿支持。未置位时，上位机不会发送
  `SET_POSE`，以兼容当前 capabilities 为 0 的旧固件。

## 固件侧实施顺序

1. **读取四轮位置**：周期读取四个电机驱动器的 `S_CPOS`，保存原始累计脉冲和采样
   时间。一次里程计更新必须使用同一周期内的四轮数据，通信失败的轮不能沿用为新值。
2. **确认轮序与方向**：在车轮离地、低速且急停可用的台架上，逐轮正转，记录物理位置
   与 `S_CPOS` 增减方向，建立前左、前右、后左、后右到驱动器地址的唯一映射。方向修正
   应在进入里程计前完成，不能在 UI 层补偿。
3. **标定脉冲每毫米**：对每个轮分别测量多次已知直线距离，计算
   `pulses_per_mm = 脉冲增量 / 实际毫米`，正反向都应验证。记录均值、离散度、轮径、减速
   比和测试载荷；不要直接采用未经实测的理论轮径参数。
4. **麦轮里程计**：把四轮脉冲增量换算为轮缘位移，根据当前轮序、滚子布局和车体几何
   参数求车体坐标系的 `dx`、`dy`、`dtheta`，再按当前航向旋转到场地坐标系积分。先用纯
   平移、纯横移、原地旋转三个台架用例验证符号，再做组合运动。
5. **融合 HWT101 航向**：将 HWT101 航向转换到本协议的零点和逆时针正方向，处理
   ±180° 跨界。编码器提供短时角速度连续性，HWT101 用于抑制长期漂移；可先使用带限幅
   的互补融合。传感器异常或时间戳倒退时保持上一可信航向并上报诊断，不能跳变到零。
6. **10 Hz 上报**：以单调毫秒时间戳生成 `POSE_TELEMETRY`，目标周期 100 ms。计算任务
   与串口发送解耦；若发送拥塞，丢弃旧样本而不是堆积陈旧位姿。Qt 页面在 500 ms 内未
   收到新样本会显示“数据超时”。
7. **初始位姿设置**：实现 `SET_POSE` 时严格检查 10 字节长度，将 x/y/yaw 原子写入定位
   状态，并重置上一轮脉冲基准，避免下一次积分把历史轮差叠加到新位姿。成功后返回空
   payload；无效范围返回协议错误且不得部分更新。
8. **能力声明**：上述读轮、里程计、融合、上报和 `SET_POSE` 均完成并经过台架验证后，
   才在 HELLO 中置 `capabilities & 0x00000001`。不要仅因识别命令号就声明能力。

## 异常与验收

- 任一轮 `S_CPOS` 超时、跳变或驱动器离线时，标记位姿无效并停止积分；保留最后可信值，
  上报明确错误。需要定义累计计数回绕处理，并用越界附近的正负计数做单元测试。
- HWT101 数据超时或校验失败时，不得悄悄把航向清零；可短时退化为编码器航向，同时输出
  降级状态。恢复时限制校正速率，避免位置突跳。
- `POSE_TELEMETRY` 必须严格为 14 字节，坐标允许负数及超出 0–2400 mm，便于暴露定位
  异常。上位机会保留原始数值，只把地图图标限制在边界并显示红色越界警告。
- 实车验收至少覆盖两个启停区初始位姿、直行/横移/原地旋转、闭合路径回零、断开单轮和
  IMU、串口中断超过 500 ms、重新设置初始位姿。记录每项误差与恢复行为。

完成以上工作前，定位页中的“本地模拟”数据必须明确视为模拟值，不能据此评价实车定位
精度，也不能把底盘动作指令积分后伪装成测量结果。
