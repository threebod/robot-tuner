# Robot Tuner 上位机

这是 Qt 6 Widgets 上位机，同时支持版本 1 的 `host_protocol` 二进制调试模式和
`test/mecanum_jog` 文本调试模式。
本目录的自动化测试使用内存中的 `FakeDevice`，不需要串口或机器人硬件。

## Windows 环境

推荐使用已经准备好的 Qt/MinGW 工具链，不在本项目中安装依赖，也不要把依赖复制到
C 盘：

- Qt 6.11.1 MinGW 64-bit：`E:\Qt\6.11.1\mingw_64`
- MinGW 13.1：`E:\Qt\Tools\mingw1310_64\bin`
- CMake 3.22 或更高版本（本机为 3.30.5）：`E:\Qt\Tools\CMake_64\bin`（CTest 的 Qt
  `ENVIRONMENT_MODIFICATION` 需要 3.22+）
- Ninja 1.12.1：`E:\Qt\Tools\Ninja`

在 PowerShell 中配置本次会话的 PATH（路径顺序有意固定），然后从本目录执行：

```powershell
$qtPrefix = 'E:\Qt\6.11.1\mingw_64'
$mingwBin = 'E:\Qt\Tools\mingw1310_64\bin'
$cmakeBin = 'E:\Qt\Tools\CMake_64\bin'
$ninjaBin = 'E:\Qt\Tools\Ninja'
$env:Path = "$mingwBin;$qtPrefix\bin;$cmakeBin;$ninjaBin;$env:Path"

cmake -S . -B build -G Ninja `
    -DCMAKE_BUILD_TYPE=Debug `
    -DCMAKE_PREFIX_PATH="$qtPrefix" `
    -DCMAKE_C_COMPILER="$mingwBin\gcc.exe" `
    -DCMAKE_CXX_COMPILER="$mingwBin\g++.exe"
cmake --build build --config Debug
ctest --test-dir build -C Debug --output-on-failure
```

`CMAKE_AUTOGEN_PARALLEL=1` 已固定 Qt 自动生成步骤的 worker 数量，以避免 Windows 上
并发 `moc.exe` 的不稳定退出。运行 GUI 时仍需保留同一 PATH：

```powershell
.\build\robot_tuner.exe
```

## 串口与固件设置

连接前先选择设备模式，再选择当前实际连接的一路链路：

- `标准调试协议` 保持原有二进制握手、参数和遥测功能；
- `mecanum_jog 文本协议` 不发送二进制 `HELLO`，使用“临时调试”页面控制实际测试
  工程，原二进制业务页面在该模式下禁用。

- USB-UART 调试链路连接 STM32 `USART3` 的 `PB10/PB11`，使用 `115200 8-N-1`，无硬件流控。
- HC-05 蓝牙链路使用 STM32 `UART5`，模块链路参数设为 `115200 8-N-1`，无硬件流控。

文本模式每 250 ms 发送一次静默 `hb` 心跳。需要授权的按钮会自动先发送 `arm`，
只有收到固件的完整授权回复后才发送目标命令。顶部“急停”会立即发送单字节 `!`，
不附加换行；文本固件没有持久急停锁，因此该模式不提供“解除急停”。
串口终端默认使用 ASCII；在文本模式下，接收数据按连续文本流显示，CR/LF 直接换行，
不显示时间戳、TX/RX 前缀和自动 `hb` 心跳。切换到 HEX 后仍按原始记录格式显示。

文本模式默认使用文本发送并勾选 CRLF。终端发送统一经过文本客户端，每次只接受一条
不超过 79 字节的 ASCII 命令，并补齐 CRLF；HEX 发送也不能绕过该限制。任意包含 `!`
的发送仅执行急停。终端的 `stop`、`X/x`、`disable` 会取消待授权动作；
等待授权期间拒绝其他手动命令。固件返回 `ERR` 时，临时调试页和终端都会显示错误。

文本模式下“场地定位”页切换为安全航点导航：先选择实际摆放的启停区初始化，再点击地图选择最近安全航点、选择10～120 RPM，最后点击“移动到目标”。当前位置和航向来自固件的命令积分估计，不是真实定位；页面会用独立标记区分当前点与目标点。停止、急停、断连或固件故障后必须把车放回启停区并重新初始化。标准调试协议下该页面仍保持原有位姿同步行为。

临时调试页不再提供独立手动使能区，各运动按钮执行单次 `arm` 握手后由固件自动使能对应电机。普通停止按钮和全局急停仍保留。定距按100 mm步进，底盘测试转速上限为120 RPM；辅助电机可选择CAN地址5或6进行短点动。舵机2～4使用角度滑块，松开滑块时发送目标角度。路线区可在底盘空闲时把横移距离比例实时调整为50.00%～150.00%；设置只保存在固件 RAM，重启后恢复默认87.62%。

文本模式下新增“动作录入”页。先把机构人工放到设定姿态并点击“确认人工初始姿态”，
再添加组合姿态、夹爪、平台、舵机或等待步骤。可测试选中步骤、从选中步骤开始、完整测试
一次、停止以及回到自定义初始位置。动作可保存为 JSON，也可导出为 `mechanism_action.h`
兼容的 C 表。姿态步骤使用 5/6 号电机与转台的估算位置；没有编码器回零或限位反馈，
停止、急停、断连或故障后必须人工复位并重新初始化。电机速度超过 120 RPM 时会再次确认。

文本固件只有单条接收槽，且没有统一的回复结束标记，因此文本模式禁用自动循环发送，
预设条目仍可逐条手动发送。标准协议模式保留循环发送；全局急停会先停止所有串口面板的
循环，取消当前周期剩余条目，再发送急停命令。

动作测试页中的舵机目标调试支持舵机 2、3 的 `0–270°` 和舵机 4 的 `0–360°`。
滑块只改变目标值；点击“发送目标角度”并确认后才发送。下方记录仅表示已发送的目标角度，
不表示舵机已到位，也不会写入文件或提供回放。

固件 `yyb_stm32/host_protocol/host_config.h` 中 `HOST_DEBUG_MODE` 默认是 `1`。调试上位机
时保持为 `1`；需要恢复旧的主循环时显式编译为 `0`。该宏控制固件调试入口，不是上位机
运行时选项；两种固件模式都必须在 Keil 环境分别构建后再进行硬件验收。

## 安全首启流程

首次上电前断开电机/执行器或确保机械部分已可靠架空，手边保持物理急停可用。先检查
串口号和波特率，连接后只观察 `HELLO`、状态、参数读取和低频遥测；确认方向、限位、
看门狗和急停方案后，才允许使用 `TEST_UNLOCK` 和小范围动作测试。发现异常立即使用
物理急停，并断开上位机连接。软件测试通过不等于机器人硬件验收通过。

参数写入只存在 STM32 RAM 中，不写 Flash/EEPROM；STM32 重启后会恢复固件默认参数。
因此每次重启都应重新读取并核对参数，不能把上位机显示的上一次值当作持久化配置。
