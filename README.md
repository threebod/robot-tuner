在“场地定位”页输入任务码，例如 `156+123+516+231`，再点击“开始两轮完整取放”。
上位机先下发 `task <任务码>`，收到对应的 `TASK SET code=...` 确认后才继续启动准备。
第一、三组指定两批的颜色与取料顺序（红1、黄2、蓝3、绿4、黑5、浅蓝6）；
第二组指定第一批在粗加工区和暂存区的位置，第四组仅指定第二批在粗加工区的位置，每组须为1、2、3的排列。第二批暂存根据第一层的颜色位置同色码垛，不使用第四组。
物料依次进入平台槽1、2、3，粗加工取回后仍回原槽；第二批暂存沿用第二层高度。
粗加工和第一层暂存按圆环2→1→3放置，第二批第二层码垛按圆环1→2→3放置；均按任务码选择各圆环对应的平台槽。
每批到取料区后先用任意颜色物块的中心对准，再按任务码顺序确认夹取；取料偏差超出横纵各±30像素时重新微调并停稳复检，连续两次确认在容差内才夹取。
取料、圆环和码垛观察的水平位置为-770（较前版-720再回退5 mm，较原-500累计回退27 mm），竖直位置不变；每件取料视觉识别期间升降轴仍提前下降50 mm，下降完成并重新确认目标后才夹取；两轮取料区出口均将对准补偿与右移50 mm合为一次移动。
物理圆环1、2、3分别对应云台306.5°、265.7°、232°。非法任务码不启动准备，运行中禁止修改。
粗加工回收第一轮平台水平位置为-450（较此前-500少回退5 mm），第二轮按指定位置-470（-47 mm）放回；下降、松爪和抬升阶段保持对应轮次的位置。
路线取料联调 `route rawpick` 仍按绿、黄、浅蓝顺序执行。

PC9离线启动：当前固件上电自动按已确认的水平/升降零位、云台65°、夹爪35°、平台26°准备，默认200 RPM，物料和圆环2比例为前后640、左右673。无需连接上位机，舵机到位后短按松开PC9从启停区1出发，长按满1秒从启停区2出发，松开不重复启动。扫码点至少停车1秒，并等待合法四组扫码任务码；该结果决定两轮取放，覆盖上位机预先下发的任务码。上位机准备按钮仍可覆盖速度及视觉比例。PC9一端接PC9、另一端接GND，内部上拉和30 ms消抖；上电按住须先松开再按。

PC9准备及按键启动的任务不依赖上位机心跳；上位机直接启动的任务仍保留1秒心跳超时保护。停止、急停、CAN/IMU/视觉通信故障保护保持。取消或结束后须核实机构姿态、恢复零位，再重新准备或重新上电；不会自动续跑。
需要同步部署当前STM32固件与MaixCAM2 v1.0.6相机程序，旧相机未知颜色不会触发自动夹取。

## Windows 环境

推荐使用已经准备好的 Qt/MinGW 工具链，不在本项目中安装依赖，也不要把依赖复制到
C 盘：

- Qt 6.11.1 MinGW 64-bit：`E:\Qt\6.11.1\mingw_64`
- MinGW 13.1：`E:\Qt\Tools\mingw1310_64\bin`
- CMake 3.22 或更高版本（本机为 3.30.5）：`E:\Qt\Tools\CMake_64\bin`（CTest 的 Qt
  `ENVIRONMENT_MODIFICATION` 需要 3.22+）
- Ninja 1.12.1：`E:\Qt\Tools\Ninja`

在 PowerShell 中配置本次会话的 PATH（路径顺序有意固定），然后从本目录执行：

```powershell
$qtPrefix = 'E:\Qt\6.11.1\mingw_64'
$mingwBin = 'E:\Qt\Tools\mingw1310_64\bin'
$cmakeBin = 'E:\Qt\Tools\CMake_64\bin'
$ninjaBin = 'E:\Qt\Tools\Ninja'
$env:Path = "$mingwBin;$qtPrefix\bin;$cmakeBin;$ninjaBin;$env:Path"

cmake -S . -B build -G Ninja `
    -DCMAKE_BUILD_TYPE=Debug `
    -DCMAKE_PREFIX_PATH="$qtPrefix" `
    -DCMAKE_C_COMPILER="$mingwBin\gcc.exe" `
    -DCMAKE_CXX_COMPILER="$mingwBin\g++.exe"
cmake --build build --config Debug
ctest --test-dir build -C Debug --output-on-failure
```

`CMAKE_AUTOGEN_PARALLEL=1` 已固定 Qt 自动生成步骤的 worker 数量，以避免 Windows 上
并发 `moc.exe` 的不稳定退出。运行 GUI 时仍需保留同一 PATH：

```powershell
.\build\robot_tuner.exe
```

## 串口与固件设置

### 圆环 2 自动标定

连接 `mecanum_jog 文本协议`，在“视觉微调”选择“圆环 → 圆环 2”，点击“自动标定圆环 2 比例”。
请先将相机和机构置于实际圆环识别姿态，保持圆环 2 在画面内，并确认前后、左右各 20 mm 的净空。
程序以 15 RPM 自动前移 20 mm、后移返回、右移 20 mm、左移返回，每次停稳 300 ms 后读取稳定圆环中心，
使用两个方向的像素变化平均值计算前后、左右的 mm/像素，然后自动填写比例并等待主控应用确认。
往返中心偏差大于 3 像素、轴间耦合过大、方向不符、像素变化过小或超出比例范围时，不应用计算值。
标定期间其他运动入口锁定；“停止标定”、全局急停、通信故障或断连都会取消流程，不会自动继续或盲目回位。

此功能需要同步更新 `test/mecanum_jog` 固件，摄像头程序沿用当前版本。新增的只采样命令为
`vision sample ring 2 ID`（ID 为 1～65535），回复为 `VISION MEASURE id=... ring=2 token=... du=... dv=... quality=...`。
只采样不会按旧比例移动底盘，也不要求旧比例已经标定。标定值沿用现有 RAM 行为：主控断电后须重新应用，
上位机退出后输入值恢复初值。此比例使用底盘点动指令距离计算，用于同一姿态下的视觉矫正，不替代底盘实际距离标定。
对准仍先执行完整换算位移，停稳后重新识别，超差再补调；圆环采用横纵各 ±2 像素及两轮确认，最多 12 次修正。
自动标定和一次移动到位的实机效果尚未验证。

### 路线编辑

“路线编辑”页可离线编辑步骤，连接 `mecanum_jog 文本协议` 后逐步下发执行。
支持相对移动、左右转向、物料／圆环视觉对准、导入动作组、等待和人工确认；
步骤可添加、修改、复制、删除、上下排序，并保存／打开 JSON。
移动方向相对执行时的当前车头，距离单位为 mm；转向后，后续移动沿新的车头方向。
视觉对准先应用该步骤的前后／左右比例，以对准后的位置继续，不回退微调距离。
物料对准不自动抓取，可在其后添加取料动作组；观测姿态须在视觉步骤前通过动作组准备。

导入的动作组完整内容保存在路线文件中。修改机构动作时，在“动作录入”页修改动作组后，
重新导入并点击“修改选中”。执行前须准备并初始化机构，夹爪、平台及机构姿态必须与
该动作组的初始状态一致；路线不会使用 `mech init` 伪造到位状态。
路线支持测试选中步骤、从选中步骤开始、整段运行和停止；人工确认步骤需点击“确认并继续”。
等待当前步骤完成后才执行下一步，运行期间锁定其他运动页面，全局急停仍有效。
断连、授权超时或设备错误取消路线，不能自动原地续跑。

该功能需要同步更新 `test/mecanum_jog` 固件，增加 `move` 指令和机构舵机状态反馈。
旧固件拒绝新指令或缺少反馈时，路线停止并提示错误。固件移动距离为速度积分估算，
界面完成状态不表示已经验证实物距离或取放结果。上位机需全程连接。

连接前先选择设备模式，再选择当前实际连接的一路链路：

- `标准调试协议` 保持原有二进制握手、参数和遥测功能；
- `mecanum_jog 文本协议` 不发送二进制 `HELLO`，使用“临时调试”页面控制实际测试
  工程，原二进制业务页面在该模式下禁用。

- USB-UART 调试链路连接 STM32 `USART3` 的 `PB10/PB11`，使用 `115200 8-N-1`，无硬件流控。
- HC-05 蓝牙链路使用 STM32 `UART5`，模块链路参数设为 `115200 8-N-1`，无硬件流控。

文本模式每 250 ms 发送一次静默 `hb` 心跳。需要授权的按钮会自动先发送 `arm`，
只有收到固件的完整授权回复后才发送目标命令。顶部“急停”会立即发送单字节 `!`，
不附加换行；文本固件没有持久急停锁，因此该模式不提供“解除急停”。
串口终端默认使用 ASCII；在文本模式下，接收数据按连续文本流显示，CR/LF 直接换行，
不显示时间戳、TX/RX 前缀和自动 `hb` 心跳。切换到 HEX 后仍按原始记录格式显示。

文本模式默认使用文本发送并勾选 CRLF。终端发送统一经过文本客户端，每次只接受一条
不超过 79 字节的 ASCII 命令，并补齐 CRLF；HEX 发送也不能绕过该限制。任意包含 `!`
的发送仅执行急停。终端的 `stop`、`X/x`、`disable` 会取消待授权动作；
等待授权期间拒绝其他手动命令。固件返回 `ERR` 时，临时调试页和终端都会显示错误。

文本模式下“场地定位”页切换为安全航点导航：先选择实际摆放的启停区初始化，再点击地图选择最近安全航点、选择10～120 RPM，最后点击“移动到目标”。当前位置和航向来自固件的命令积分估计，不是真实定位；页面会用独立标记区分当前点与目标点。停止、急停、断连或固件故障后必须把车放回启停区并重新初始化。标准调试协议下该页面仍保持原有位姿同步行为。

临时调试页不再提供独立手动使能区，各运动按钮执行单次 `arm` 握手后由固件自动使能对应电机。普通停止按钮和全局急停仍保留。定距按100 mm步进，底盘测试转速上限为120 RPM；辅助电机可选择CAN地址5或6进行短点动。舵机2～4使用角度滑块，松开滑块时发送目标角度。路线区可在底盘空闲时分别调整纵向、横向距离比例（50.00%～150.00%）和转向转速上限（10～120 RPM）；平移转速在地图导航和完整跑图区域直接选择。运行参数只保存在固件 RAM，重启后恢复纵向100%、横向90%、转向30 RPM。

文本模式下新增“动作录入”页。先把机构人工放到设定姿态并点击“确认人工初始姿态”，
再添加组合姿态、夹爪、平台、舵机或等待步骤。可测试选中步骤、从选中步骤开始、完整测试
一次、停止以及回到自定义初始位置。动作可保存为 JSON，也可导出为 `mechanism_action.h`
兼容的 C 表。姿态步骤使用 5/6 号电机与转台的估算位置；没有编码器回零或限位反馈，
停止、急停、断连或故障后必须人工复位并重新初始化。电机速度超过 120 RPM 时会再次确认。

文本固件只有单条接收槽，且没有统一的回复结束标记，因此文本模式禁用自动循环发送，
预设条目仍可逐条手动发送。标准协议模式保留循环发送；全局急停会先停止所有串口面板的
循环，取消当前周期剩余条目，再发送急停命令。

动作测试页中的舵机目标调试支持舵机 2、3 的 `0–270°` 和舵机 4 的 `0–360°`。
滑块只改变目标值；点击“发送目标角度”并确认后才发送。下方记录仅表示已发送的目标角度，
不表示舵机已到位，也不会写入文件或提供回放。

固件 `yyb_stm32/host_protocol/host_config.h` 中 `HOST_DEBUG_MODE` 默认是 `1`。调试上位机
时保持为 `1`；需要恢复旧的主循环时显式编译为 `0`。该宏控制固件调试入口，不是上位机
运行时选项；两种固件模式都必须在 Keil 环境分别构建后再进行硬件验收。

## 安全首启流程

首次上电前断开电机/执行器或确保机械部分已可靠架空，手边保持物理急停可用。先检查
串口号和波特率，连接后只观察 `HELLO`、状态、参数读取和低频遥测；确认方向、限位、
看门狗和急停方案后，才允许使用 `TEST_UNLOCK` 和小范围动作测试。发现异常立即使用
物理急停，并断开上位机连接。软件测试通过不等于机器人硬件验收通过。

参数写入只存在 STM32 RAM 中，不写 Flash/EEPROM；STM32 重启后会恢复固件默认参数。
因此每次重启都应重新读取并核对参数，不能把上位机显示的上一次值当作持久化配置。

两轮完整任务、PC9启动及底盘跑图改为主控逐段距离执行：每段从0累计指令估算距离，不使用全图X/Y判定到达。上位机通过 `ROUTE DIST index=... direction=... distance_mm=... progress_mm=... yaw_cdeg=... state=... stage=...` 显示方向、已走/目标距离及转向状态，完成消息为 `ROUTE DONE mode=DISTANCE`；距离消息不更新地图位置。原 `ROUTE POS`/坐标完成消息仍保留接收兼容。独立的人工地图导航不受此变更影响。

启停区1和2的固件路线分别保存在 `routeDistanceZone1`、`routeDistanceZone2`，各自独立包含完整18段距离和朝向；上位机及PC9只选择对应路线表，修改其中一套不会改动另一套的距离或转向。
